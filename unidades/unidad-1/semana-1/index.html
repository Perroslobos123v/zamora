Preguntas Finales

Las 32 preguntas del documento de Arquitectura de Software, respondidas de forma clara y sencilla y presentadas como una nueva misión del portafolio digital.

Las 32 preguntas del documento de Arquitectura de Software, respondidas de forma clara y sencilla y presentadas como una nueva misión del portafolio digital.

Q01

Base de datos utilizada

Una base de datos que he utilizado como consumidor es la de un sistema académico universitario. Puede contener entidades como Estudiante, Curso, Docente, Matrícula, Sección y Calificación. Por ejemplo, un estudiante se matricula en varios cursos y cada matrícula se relaciona con sus calificaciones.

Q02

Grupos de usuarios

Los principales grupos de usuarios pueden ser estudiantes, docentes, personal administrativo, coordinadores académicos y administradores de la base de datos. Cada grupo utiliza la información según sus funciones y permisos.

Q03

Aplicación de un grupo de usuarios

Para los estudiantes, una aplicación puede ser el portal académico. Permite consultar cursos matriculados, horarios y calificaciones mediante formularios y reportes.

Q04

Persistencia

La persistencia significa que los datos permanecen almacenados después de terminar una sesión o apagar el sistema. La información queda disponible para futuras consultas y operaciones.

Q05

Interrelación

La interrelación significa que los datos están relacionados entre sí. Por ejemplo, un estudiante se relaciona con sus matrículas, cursos y calificaciones, permitiendo consultar información conectada.

Q06

Compartir

Compartir significa que diferentes usuarios o áreas pueden utilizar los mismos datos de una base de datos de acuerdo con sus permisos. Esto evita duplicaciones y facilita trabajar con información común y actualizada.

Q07

¿Qué es un DBMS?

Un DBMS o sistema de administración de bases de datos es el software que permite definir, almacenar, consultar, actualizar y administrar una base de datos. También ayuda a controlar el acceso y el procesamiento de transacciones.

Q08

Acceso procedural y no procedural

El acceso procedural indica cómo realizar paso a paso las operaciones para obtener los datos. El acceso no procedural indica qué datos se necesitan sin detallar cada paso de acceso. La principal diferencia es que el segundo deja al DBMS decidir cómo ejecutar la consulta.

Q09

Importancia del acceso no procedural

El acceso no procedural es importante porque permite obtener información sin escribir código detallado para recorrer los datos. Esto mejora la productividad del software y facilita el desarrollo y mantenimiento de aplicaciones.

Q10

Acceso no procedural y productividad

La conexión es directa: formularios y reportes pueden especificar los requerimientos de datos mediante consultas, mientras el DBMS se encarga de encontrar y recuperar la información. Por ello, el acceso no procedural puede reducir código y facilitar el desarrollo de aplicaciones.

Q11

Formulario y reporte

Un formulario está orientado principalmente a ingresar, modificar o consultar información de manera interactiva. Un reporte presenta información organizada para lectura, análisis, impresión o toma de decisiones.

Q12

Interfaz de lenguaje procedural

Es el mecanismo que permite combinar el acceso no procedural a una base de datos con un lenguaje de programación procedural, como COBOL o Visual Basic. Así, una aplicación puede ejecutar consultas y operaciones de la base de datos dentro de un programa.

Q13

Transacción

Una transacción es una unidad de trabajo que debe procesarse de forma completa y confiable. Por ejemplo, registrar una matrícula puede implicar varias operaciones que deben quedar correctamente realizadas para conservar la consistencia.

Q14

Funciones del DBMS para transacciones

El DBMS proporciona funciones para controlar transacciones, mantener la consistencia, manejar el acceso concurrente y recuperar la información cuando ocurre una falla. De esta manera, las operaciones se procesan de forma confiable.

Q15

Transacción de la base de datos elegida

Una transacción puede ser la matrícula de un estudiante en un curso. Se utiliza especialmente al inicio de cada periodo académico y puede ser enviada por muchos estudiantes al mismo tiempo. La cantidad exacta depende de la institución y de la carga del sistema.

Q16

DBMS corporativo

Es un DBMS diseñado para organizaciones y grandes bases de datos, con muchos usuarios simultáneos. Suele ejecutarse en servidores potentes y soporta procesamiento de transacciones, disponibilidad, seguridad y rendimiento.

Q17

DBMS de escritorio

Es un DBMS que se ejecuta normalmente en computadoras personales o servidores pequeños. Soporta un procesamiento más limitado y resulta apropiado para equipos de trabajo y negocios pequeños.

Q18

DBMS embebido

Es un DBMS que reside dentro de un sistema más grande, como una aplicación o dispositivo. Ofrece procesamiento transaccional limitado y requiere pocos recursos de memoria, procesamiento y almacenamiento.

Q19

Funciones de la primera generación

La primera generación se basaba principalmente en estructuras de archivos y acceso mediante programas. Permitía búsquedas secuenciales y aleatorias, pero el usuario necesitaba escribir programas para obtener la información y existía poco soporte para relacionar datos.

Q20

Funciones de la segunda generación

La segunda generación incorporó DBMS reales capaces de administrar muchas entidades y relaciones. Se caracterizó por el acceso navegacional, donde el programador debía escribir código para navegar entre registros relacionados; algunos productos utilizaron estándares como CODASYL.

Q21

Funciones de la tercera generación

La tercera generación se caracterizó por los DBMS relacionales y los lenguajes no procedurales. El acceso mediante relaciones y operadores, junto con la optimización de tecnología, permitió consultar datos de manera más flexible y eficiente.

Q22

Funciones de la cuarta generación

La cuarta generación incorporó capacidades orientadas a objetos y soportó funciones como multimedia, procesamiento distribuido, operadores más poderosos y procesamiento de datos para data warehouse, además de nuevas posibilidades de integración.

Q23

Tres niveles del esquema

Nivel externo: presenta las vistas de información que necesita cada tipo de usuario. Nivel conceptual: representa la estructura lógica global de entidades, atributos y relaciones. Nivel interno: describe cómo se almacenan físicamente los datos, incluyendo estructuras e índices.

Q24

Propósito del mapeo

El mapeo relaciona los niveles externo, conceptual e interno y permite transformar una vista de usuario en la representación lógica y luego en la forma de almacenamiento. El DBMS es responsable de realizar y administrar estos mapeos.

Q25

Arquitectura de tres esquemas e independencia

La separación entre los niveles permite cambiar detalles de un nivel sin modificar necesariamente los otros. Por ejemplo, cambiar la forma física de almacenamiento puede hacerse sin cambiar las vistas de los usuarios. Esto reduce los costos de mantenimiento del software.

Q26

Interacción de usuarios con la base de datos

Los usuarios funcionales activos interactúan directamente con formularios, consultas y reportes. Los usuarios pueden trabajar con vistas externas de la información según sus necesidades, mientras el DBMS gestiona el acceso a los datos.

Q27

Cliente-servidor y división del procesamiento

El procesamiento se divide para aprovechar las capacidades del cliente y del servidor. El cliente puede manejar la interfaz y parte de la lógica, mientras el servidor administra los datos y las operaciones del DBMS. El servidor no hace todo porque distribuir la carga puede mejorar el uso de recursos y la respuesta.

Q28

Datos en varias computadoras

En una arquitectura cliente-servidor o distribuida, los datos pueden almacenarse en varias computadoras para repartir la carga, acercar la información a diferentes ubicaciones, mejorar el rendimiento y aumentar la disponibilidad del sistema.

Q29

Usuarios indirectos, paramétricos y poderosos

Los usuarios indirectos reciben información mediante reportes preparados. Los usuarios paramétricos utilizan formularios o consultas con parámetros definidos, por ejemplo, seleccionando un curso o periodo. Los usuarios poderosos o experimentados realizan consultas más flexibles y pueden crear o adaptar formularios y reportes.

Q30

Usuario funcional activo y analista

El usuario funcional activo trabaja directamente con la información mediante las aplicaciones de la organización. El analista estudia requerimientos, diseña soluciones y participa en el desarrollo de sistemas. Ambos utilizan principalmente el nivel externo para entender las necesidades, mientras el analista también debe considerar la estructura conceptual.

Q31

Objetivo profesional

Como objetivo a largo plazo elegiría ser administrador de bases de datos, porque me interesa la tecnología, la gestión de información y el funcionamiento de los sistemas. Este puesto me permitiría trabajar en seguridad, rendimiento, disponibilidad y administración de bases de datos.

Q32

Nicho de los DBMS de código libre

Los DBMS de código libre ocupan un espacio importante en proyectos educativos, emprendimientos, organizaciones y empresas que buscan reducir costos de licenciamiento y contar con soluciones flexibles. También son útiles para desarrolladores y equipos que necesitan adaptar la tecnología a sus necesidades.
